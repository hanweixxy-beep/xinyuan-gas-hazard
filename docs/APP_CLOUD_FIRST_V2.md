# Android APP 2.0 云端化说明

## 用户能看到的变化

- 打开 APP 必须先登录。
- 主导航精简为“首页、登记、记录、我的”。
- 新记录先在云端建立草稿，填写内容和照片自动保存。
- 最终提交时，服务器检查门头照片和未清零隐患照片是否齐全。
- APP 只显示当前账号录入的记录，不再提供 Excel 导出和“数据与云端”模块。
- Excel 查询和下载统一在 `https://www.gashbxy.com/admin/` 完成。

## 账号权限

后台创建账号时可选择允许登录：

- `app`：只允许登录 Android APP。
- `admin`：只允许登录电脑管理后台。
- `both`：同一账号可登录两端，适合检查人员在 APP 登记、在电脑下载本人数据。

无论账号角色如何，业务记录列表、详情和导出都按服务端识别的创建人隔离。
客户端提交的创建人参数不作为权限依据。

## 旧版数据迁移

升级安装不会覆盖旧版 Room 数据库，前提是使用相同 Android 包名和同一签名证书。
新版首次登录后会检测旧记录：

1. 用户进入一次性“历史数据迁移”页面。
2. APP 使用旧记录 UUID 逐条上传，重复执行不会重复创建。
3. 上传成功的记录保留同步标记，迁移中断后可以继续。
4. 全部上传成功后，由用户明确确认是否清理手机旧数据。

迁移前不要卸载旧 APP。应直接安装正式签名的 `2.0.0` APK 覆盖升级；卸载会清除
旧数据库和照片。

## 云端接口

- `POST /api/auth/login`：登录，APP 固定发送 `clientType=app`。
- `POST /api/records/drafts`：创建或更新云端草稿。
- `POST /api/records/drafts/submit`：校验并提交草稿。
- `GET /api/records`：读取当前账号已提交记录。
- `POST /api/uploads`：上传照片。

数据库增量迁移脚本：
`database/patches/20260728_cloud_first_accounts_drafts.sql`。

## 发布检查

1. 备份生产数据库和 `/var/www/xinyuan-gas`。
2. 执行数据库增量迁移。
3. 部署后端和前端文件并运行 PHP、Nginx 检查。
4. 用临时测试记录验证账号隔离、草稿保存、提交和照片必填校验。
5. 构建 release APK，并核对它与旧版 APK 的签名证书 SHA-256 一致。
6. 在保留旧数据的真机上覆盖安装，完成迁移和拍照水印测试。

Android 签名文件、服务器密钥、`.env` 和 APK 均不进入 Git；按
`docs/BACKUP_AND_SECRETS.md` 单独保存。
